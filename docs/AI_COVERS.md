# AI covers and illustrations

Generation providers are disabled by default and injected behind provider protocols. No credentials or publisher-specific implementation is hard-coded. An explicitly approved service can be connected with `WEBNOVEL_AI_IMAGE_PROVIDER=http`, `WEBNOVEL_AI_IMAGE_ENDPOINT`, and `WEBNOVEL_AI_IMAGE_API_KEY`; production endpoints must use HTTPS. The adapter sends a grounded JSON brief and accepts raw image bytes, while credentials are never stored in prompt metadata. Cover briefs use title, author, genre, setting, period, themes, and a spoiler-free description, with explicit constraints against copied covers, adaptation art, commercial artwork, or imitation of living artists.

The cover service creates portrait (1200×1800), thumbnail (400×600), and OpenGraph (1200×630) WebP variants under `storage/covers/<slug>`. It stores hashes, dimensions, MIME type, brief metadata, and approval state. Generated images enter an admin approval queue; publication requires all three approved variants. Reusing an approved cover is preferred to regeneration.

Chapter illustrations use an adaptive placement plan: every generated chapter receives a 16:9 hero, while chapters above 1,200, 3,000, 7,000, and 12,000 words receive one, two, three, or four interval placements respectively. Anchors are selected from complete paragraph boundaries rather than fixed word cuts. Outputs are optimized WebP files under `storage/chapter-images/<novel>/<chapter>`, and remain private until an administrator approves them. The reader eagerly loads only the hero, lazy-loads interval art, pauses offscreen animation, and disables motion under `prefers-reduced-motion`.

Each novel has a stored visual profile for period, environments, recurring-character notes, atmosphere, style, lighting, palette, motifs, and prompt constraints. Every image record retains placement, canonical-excerpt hash, full prompt, provider/model, timestamp, provenance status, dimensions, file size, animation type, fallback, alt text, and approval state. Normal page viewing never calls an image provider.

Four inspected built-in ImageGen samples exercise the local import path; their exact prompts and placement metadata are in `docs/sample-artwork-manifest.json`. Re-import them idempotently with `scripts/import_generated_artwork.py`. Bulk generation still requires an explicitly approved HTTP provider, credentials, cost limits, and safety policy; the default disabled provider is a deliberate fail-closed boundary.

Rollout is 20 covers and chapter sets, then 100, then 500, then 1,000, and progressively toward 10,000. Every gate requires rights, extraction, artwork, reader, storage, and performance review before advancing.
